# Validation Dashboard

หน้าเว็บไฟล์เดียวสำหรับอ่านผลของ `scripts/validate_pdf_extraction.py` — สคริปต์นั้นเขียน JSON/CSV
ที่ยาวเกินกว่าจะไล่อ่านเองตอนรันกับคอร์ปัสจริง (1,077 ไฟล์) หน้านี้แปลงมันเป็นรายการงานที่เรียงตามผลกระทบ

## วิธีใช้

```powershell
# 1. รัน validator (ชุดเล็กไว้ลองก่อน)
python scripts/validate_pdf_extraction.py --limit 20 --output pdf_validation_sample.json

# คอร์ปัสเต็ม — ช้า ปล่อยรันทิ้งไว้
python scripts/validate_pdf_extraction.py --output docs/test-reports/full-corpus.json
```

2. เปิด `static/validation-dashboard/index.html` ด้วยเบราว์เซอร์ (ดับเบิลคลิกได้เลย ไม่ต้องมี server)
3. ลากไฟล์ `.json` ที่ได้มาวาง หรือกดปุ่มเลือกไฟล์ — รับไฟล์ `.csv` จาก `--csv` ด้วย

ทุกอย่างทำงานในเบราว์เซอร์ ไม่มีการส่งข้อมูลออกไปข้างนอก รายงานล่าสุดถูกจำไว้ใน
`localStorage` เพื่อให้เปิดหน้าใหม่แล้วไม่ต้องลากไฟล์ซ้ำ

## การจัดกลุ่มไฟล์

| กลุ่ม | เงื่อนไข | ทำไมต้องสนใจ |
|---|---|---|
| **ล้มเหลว** | `error` ไม่ว่าง | extract ไม่ผ่าน — มี error ชัดเจน |
| **น่าสงสัย** | ไม่มี error แต่ไม่มีหน้า/ไม่ได้ข้อความ หรือได้ < N ตัวอักษรต่อหน้า | **พังเงียบๆ** pipeline บอกว่าสำเร็จแต่ผลใช้งานไม่ได้ — เป็นบั๊กคลาสเดียวกับที่เจอ 2026-09-17 (ไฟล์ที่ไม่ใช่ PDF ถูกรายงานว่าถอดสำเร็จ) |
| **ต้อง OCR** | ได้ข้อความ แต่มีหน้าที่ต้อง OCR | สำเร็จ แต่ช้าและมีโอกาสอ่านเพี้ยน |
| **สะอาด** | ได้ข้อความจาก text layer ตรงๆ | ไม่ต้องทำอะไร |

เกณฑ์ "บางกว่า N ตัวอักษร/หน้า" ปรับได้ที่แถบตัวกรองด้านบน (ค่าเริ่มต้น 50) ค่าที่ตั้งถูกจำไว้ในเบราว์เซอร์

## สิ่งที่ดูได้

- **ตัวเลขนำ** — จำนวนไฟล์ที่ต้องตามต่อ (ล้มเหลว + น่าสงสัย)
- **สุขภาพของคอร์ปัส** — สัดส่วนแต่ละกลุ่ม กดที่แถบเพื่อกรองตารางด้านล่าง
- **สาเหตุที่ล้มเหลว** — จัดกลุ่ม error ที่ข้อความเหมือนกัน (ตัด path และตัวเลขออก เช่น
  `timed out after 120s` → `timed out after Ns`) เรียงตามจำนวนไฟล์ กดเพื่อดูรายชื่อไฟล์
- **เวลาที่ใช้ต่อไฟล์** — histogram + ประมาณเวลารันคอร์ปัสเต็มจากค่าเฉลี่ยที่วัดได้จริง
- **ตารางรายไฟล์** — เรียง/ค้นหาได้ คัดลอก path ของชุดที่กรองอยู่ หรือดาวน์โหลดเป็น CSV
  ไปวิเคราะห์ต่อ

## หมายเหตุ

หน้านี้ไม่มี build step และไม่มี dependency — เป็น HTML/CSS/JS ไฟล์เดียว โหลดฟอนต์จาก
Google Fonts (ออฟไลน์จะ fallback เป็นฟอนต์ระบบ) เหมือนกับ `docs/test-reports/`
